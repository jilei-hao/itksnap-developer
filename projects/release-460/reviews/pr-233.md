## Verdict

**Merge, preferably with two small follow-ups: a geometry check instead of a size check, and a
message instead of a silent no-op.**

The PR matters more now than when it was written. seg_anchor, which landed after it, lets a
segmentation keep its own voxel grid. That made the case the second commit guards against easy to
reach, and on current master it crashes ITK-SNAP.

## Measured

**On master, the adaptive brush crashes when the segmentation has its own grid.**
- Setup: load `MRIcrop-orig.gipl.gz` (78×110×64, 1 mm), then `MRIcrop-seg-hippoL-04mm.nii.gz` as the
  segmentation (82×135×92, 0.4 mm), both from `Testing/TestData`. Choose the adaptive paintbrush and
  click in the axial view on slice 85.
- Result: ITK-SNAP aborts with an uncaught `itk::InvalidRequestedRegionError`, every run.
- Why:
  - `ApplyBrush` builds the region to process (`xTestRegion`) in the **segmentation's** voxel indices,
    then runs the watershed on the **main image** with that same region.
  - Slice 85 exists in the segmentation's grid, but the main image has only 64 slices.
  - The key handler catches only `IRISException`, so the ITK exception ends the program.

**With #233 merged onto master:** the same clicks are refused and ITK-SNAP keeps running (23 s run).

**A key-driven test cannot catch this.** The Space key paints with `dragging = true`, and the
watershed only runs when `!dragging`. A test has to use a real mouse press
(`postMouseEvent(…, "click", "left")`).

The repro, ready to add as a GUI test, is in [pr-233-scripts/](pr-233-scripts/). It aborts on master
and passes with #233. Both were measured with the saved script.

## Read (not measured)

1. **The guard compares region sizes, not grids.**
   `img_source->GetBufferedRegion() != imgLabel->GetImage()->GetBufferedRegion()` compares index and
   size only. A segmentation with the image's size but another spacing, origin or direction passes,
   and the watershed then runs on grey voxels at other physical positions. The result is a silently
   wrong brush stroke. seg_anchor keeps segmentation headers, so this is reachable. Comparing spacing,
   origin and direction as well would close it. `ImageWrapperBase::IsSameGeometry` may already do
   this.
   - Not measured: the harness reads values at the cursor, but a click paints under the mouse, and
     the Undo action's state does not update in the harness. A control run with a matching grid also
     showed Undo disabled.
2. **The refusal is silent.** `return false` means the user clicks and nothing happens. Throwing an
   `IRISException` would show a warning, now that the handlers catch `std::exception`. For example: "The
   adaptive brush works only when the image and the segmentation share the same voxel grid". An
   alternative is to disable the Adaptive button in that case.
3. **A design question for Paul:** should the adaptive brush resample the grey image into the
   segmentation's grid, as the slice display does, instead of refusing? Refusing is safe for 4.6.
4. **The rest is good:**
   - catching `std::exception` in all four handlers;
   - releasing the cast pipeline on a throw (`catch (...) { release; throw; }`);
   - the null check on `img_source`.
5. **The PR description** describes the first version. It still says "crop `xTestRegion`", which
   the second commit replaced with the grid check.
